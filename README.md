# Наш дом — канбан для домашних дел

Общая доска задач для семьи или любой небольшой команды. Колонки To Do, In Progress, Review и Done. Задачи назначаются пользователям, которые выглядят как цветные магниты на холодильнике.

## Запуск

```bash
./run.sh
```

Откройте http://localhost:8000. При первом входе приложение попросит создать первого пользователя. Он станет администратором и сможет добавить остальных через «Люди».

Сервер слушает все интерфейсы, так что с телефона в той же Wi‑Fi сети доска открывается по адресу `http://<IP-компьютера>:8000`.

### Настройки

Настройки хранятся в файле `.env` в корне проекта. Шаблон лежит в `.env.example`:

```bash
cp .env.example .env
```

Файл `.env` внесён в `.gitignore`, так что токен не попадёт в репозиторий. Те же параметры можно задать переменными окружения, и тогда они важнее значений из файла. Изменения в `.env` применяются после перезапуска сервера.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `TODO_DB` | `data/tasks.db` | путь к файлу SQLite |
| `HOST` | `0.0.0.0` | адрес сервера |
| `PORT` | `8000` | порт |
| `TELEGRAM_BOT_TOKEN` | — | токен бота; без него уведомления выключены |
| `TELEGRAM_DIGEST_HOUR` | `9` | час утренней сводки (по времени сервера) |
| `TODO_PUBLIC_URL` | — | адрес доски; если задан, ссылка на неё добавляется в сообщения |

## Уведомления в Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и скопируйте токен.
2. Вставьте токен в `.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC...
   ```
   Затем перезапустите `./run.sh`.
3. Каждый пользователь открывает «Люди», нажимает «Подключить Telegram» и в открывшемся чате с ботом нажимает «Start».

Бот присылает:
- новую задачу или передачу задачи вам;
- просьбу проверить, когда вашу задачу переносят в Review;
- отметку о выполнении задачи, которую вы создали или которая назначена вам, вместе с начисленными очками;
- комментарии к вашим задачам;
- утреннюю сводку: что сделать сегодня, что просрочено и что на завтра.

О своих собственных действиях вы уведомлений не получаете. Команды бота: `/tasks` показывает ваши открытые задачи, `/stop` отключает уведомления.

## Что умеет

- **Доска** с четырьмя колонками. Карточки перетаскиваются между колонками и внутри колонки, порядок сохраняется.
- **Пользователи.** Вход по логину и паролю. Администратор добавляет и удаляет людей и выдаёт права администратора. Каждый может поменять своё имя, цвет и пароль.
- **Задачи.** У задачи есть исполнитель, срок, важность («можно потом», «обычная», «срочно»), категория и описание.
- **Повторяющиеся дела** (каждый день, неделю или месяц). Когда такая задача попадает в Done, в To Do автоматически появляется следующая со сдвинутым сроком.
- **Сроки на карточках.** Задачи на сегодня подсвечены жёлтым, просроченные — красным.
- **Фильтры** по человеку и по категории, плюс поиск по тексту.
- **Чек-листы внутри задачи**, например список покупок. Прогресс виден на карточке. У повторяющихся задач чек-лист переходит в следующий повтор со снятыми галочками.
- **История и комментарии.** В карточке задачи видно, кто её создал, переносил, переназначал и что менял, а рядом можно переписываться.
- **Очки и рейтинг.** Каждой задаче даётся от 1 до 8 очков. Когда задача попадает в Done, очки получает исполнитель. Рейтинг считается за неделю, за месяц и за всё время.
- **Статистика** в окне «Люди»: сколько задач в работе и сколько сделано за неделю.
- **Done не захламляется.** Задачи, выполненные больше 14 дней назад, скрываются за кнопкой «Показать старые».
- **Автообновление.** Доска обновляется раз в 30 секунд и при возврате на вкладку, так что изменения других членов семьи видны без перезагрузки.
- Есть тёмная тема и мобильная вёрстка: колонки листаются свайпом, а колонку задачи можно сменить в её карточке.

Обновление существующей базы происходит автоматически при запуске: схема хранит номер версии и применяет только недостающие миграции.

## Устройство

```
app/
  main.py        FastAPI: API и раздача статики
  db.py          схема SQLite
  security.py    хеширование паролей (PBKDF2), токены сессий
  recurrence.py  расчёт следующей даты для повторяющихся задач
  telegram.py    бот, очередь уведомлений, утренняя сводка
  config.py      чтение .env
charts/          Helm-чарт
Dockerfile       образ (distroless, non-root)
.github/         CI: тесты, линтеры, сборка и сканирование образа
  __main__.py    запуск сервера: python -m app
  static/        фронтенд на чистом JS, без сборки
tests/           pytest-тесты API
```

### API

Все эндпоинты, кроме входа и первичной настройки, требуют cookie сессии.

| Метод | Путь | Назначение |
|---|---|---|
| GET/POST | `/api/setup` | проверить, нужен ли первый пользователь, или создать его |
| POST | `/api/login`, `/api/logout` | вход и выход |
| GET | `/api/me` | текущий пользователь |
| GET/POST | `/api/users` | список пользователей и добавление (только администратор) |
| PATCH/DELETE | `/api/users/{id}` | изменение и удаление пользователя |
| GET/POST | `/api/tasks` | список задач (фильтры `assignee_id`, `category`, `q`) и создание |
| GET/PATCH/DELETE | `/api/tasks/{id}` | одна задача |
| POST | `/api/tasks/{id}/move` | перенос `{status, index}` |
| POST | `/api/tasks/{id}/checklist` | добавить пункт чек-листа |
| PATCH/DELETE | `/api/checklist/{id}` | изменить или удалить пункт |
| GET | `/api/tasks/{id}/events` | история и комментарии |
| POST | `/api/tasks/{id}/comments` | написать комментарий |
| DELETE | `/api/events/{id}` | удалить комментарий (автор или администратор) |
| GET | `/api/leaderboard?period=week\|month\|all` | рейтинг по очкам |
| GET | `/api/config` | включён ли Telegram |
| POST/DELETE | `/api/me/telegram` | получить ссылку для привязки или отвязать Telegram |
| GET | `/api/categories` | список категорий |
| GET | `/api/stats` | статистика по людям |

Интерактивная документация доступна на `/docs`.

## Контейнер

Образ собирается в GitHub Actions при каждом push в `main` и при тегах `v*.*.*`, публикуется в `ghcr.io/gera-corp/to-do-board` под `linux/amd64` и `linux/arm64`.

| Тег | Когда появляется |
|---|---|
| `latest`, `sha-<коммит>` | push в `main` |
| `1.2.3`, `1.2` | тег `v1.2.3` |

Чем образ защищён:
- база — distroless (`gcr.io/distroless/python3-debian13:nonroot`): нет shell, пакетного менеджера и лишних утилит;
- процесс работает от непривилегированного пользователя `65532`;
- код принадлежит root и недоступен на запись; приложение может писать только в `/data`;
- образ работает с файловой системой только для чтения и без Linux capabilities;
- базовые образы закреплены по дайджесту, зависимости — по хешам, GitHub Actions — по SHA коммитов;
- к образу прикладываются SBOM и подписанная аттестация происхождения (provenance);
- Trivy сканирует каждый образ, отчёт попадает во вкладку Security, а критичные уязвимости с доступным исправлением останавливают сборку;
- Dependabot раз в неделю предлагает обновления базовых образов, зависимостей и экшенов.

Локальный запуск с теми же ограничениями, что в кластере:

```bash
docker run --rm -p 8000:8000 --read-only --cap-drop ALL \
  --security-opt no-new-privileges --tmpfs /tmp -v to-do-data:/data \
  ghcr.io/gera-corp/to-do-board:latest
```

## Kubernetes

Helm-чарт лежит в `charts/to-do-board`. При теге `v1.2.3` CI сначала собирает и проверяет образ `1.2.3`, а потом публикует чарт той же версии в `oci://ghcr.io/gera-corp/charts/to-do-board`.

В домашнем кластере доской управляет ArgoCD. Application и значения для кластера лежат в репозитории [gera-corp-org/argocd](https://github.com/gera-corp-org/argocd), в `home_cluster/helm_app/to-do-board`. ArgoCD следит за версиями `0.*`, поэтому выпуск новой версии выглядит так:

```bash
git tag -a v0.3.0 -m "v0.3.0" && git push origin v0.3.0
```

Через несколько минут после окончания CI ArgoCD сам обновит доску.

Основные параметры чарта:

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `ingress.host` | — | домен доски (обязателен) |
| `ingress.className` | `traefik` | IngressClass |
| `ingress.annotations` | cert-manager `letsencrypt-cloud-production` | аннотации Ingress |
| `config.timezone` | `UTC` | часовой пояс для сроков и утренней сводки |
| `config.telegramDigestHour` | `9` | час утренней сводки |
| `config.sqliteJournalMode` | `DELETE` | режим журнала SQLite; `WAL` только для локальных дисков, не NFS |
| `vault.secretPath` | `secret/data/to-do-board` | секрет в Vault (KV v2) |
| `vault.env` | `TELEGRAM_BOT_TOKEN` | какие ключи секрета подставить в переменные окружения |
| `vault.role`, `vault.authPath`, `vault.addr` | пусто | пусто — берутся настройки webhook |
| `persistence.size` | `1Gi` | размер тома для базы |
| `networkPolicy.ingressNamespaces` | `traefik` | откуда разрешён входящий трафик |

Секреты подставляет bank-vaults `vault-secrets-webhook`: в манифесте переменная выглядит как `vault:secret/data/to-do-board#TELEGRAM_BOT_TOKEN`, а реальное значение подставляется только в память процесса при старте. Ни в Kubernetes Secret, ни в etcd оно не попадает. При изменении секрета в Vault под перезапускается (`vault-secrets-reloader`).

Том с базой защищён от удаления: и `helm uninstall`, и удаление приложения в ArgoCD его не трогают.

Под запускается с профилем Pod Security `restricted`: без root, без capabilities, с `seccomp: RuntimeDefault` и файловой системой только для чтения. Реплика всегда одна, стратегия обновления — `Recreate`, потому что SQLite не поддерживает несколько писателей.
